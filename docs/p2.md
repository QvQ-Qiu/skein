# P2：常驻 Router 与主动能力

> 2026-11-19 · 在 P0/P1 之上补齐文章里的核心机制。全部默认关闭，由环境变量逐项开启。

## 1. 常驻 Router + Trigger 批处理

| 文件 | 作用 |
| --- | --- |
| `router/session.py` | 有界历史 + 待处理 Trigger 队列 |
| `router/runtime.py` | 后台取批、调用宿主、记录批次摘要 |
| `router/dispatch.py` | `build_batch_route_request` / `parse_batch_route_response` |
| `host.py` | `dispatch_batch`：一批事件只打一次模型；失败回退逐条 |
| `poll.py` | `SKEIN_ROUTER_SESSION=1` 时把事件提交给运行时 |

配置：

```ini
SKEIN_ROUTER_SESSION=0   # 1 开启；默认逐条
SKEIN_ROUTER_BATCH=8     # 单批上限
SKEIN_ROUTER_INTERVAL=0.5
```

行为：

- 采集线程只入队，不在采集线程里等模型。
- 上一轮推理期间到达的事件进入下一批；队列满丢最旧并计数。
- 历史最多 16 条，只记事件摘要与决策摘要，不存全量正文。
- 模型调用失败时回退逐条 `handle_admitted`，避免整批丢失。

## 2. 订阅直通

| 环节 | 行为 |
| --- | --- |
| 采集 | `SubscriptionForwarder` 查 `active_subscription(thread_id)` |
| 控制面 | `POST /internal/events/followup` → `ChannelHub.followup` |
| 节点 | 收到 `dispatch` + `followup=true`，用 `--resume` 续同一会话，不新建分支 |
| 回退 | 无在途 worker、控制面不可达、推送失败 → 回 Router |

配置：

```ini
SKEIN_CONTROL_URL=http://127.0.0.1:7800
```

`SKEIN_CONTROL_URL` 为空时不做直通，全部走 Router。

## 3. 上下文 Inline / Spill

`router/context.py`：

- `inline_text`：压缩空白，超过 200 字截断并加省略号。
- `spill_text`：返回窗口内摘要与窗口外剩余。
- `event_context`：只把 index、source、thread_id、摘要、字符数、是否点名、父帖 id 放进 Router 请求；完整正文留在领域库。

这是文章 Inline & Spill 的最小实现；链式召回（按引用逐跳读 Thread/Worker）留给后续。

## 4. 取消 / 停止

- `POST /internal/tickets/{id}/cancel`：向节点发 `cancel`，派工记 `failed`、工单回 `staged`。
- 工单详情抽屉在 `assigned` / `running` 时显示「取消在途」。
- 节点当前只是标记取消并丢弃结果，**不杀 cc 进程**；真正的进程级停止是后续工作。

## 5. Watchdog

`watchdog_agent.py` 是独立进程：

```bash
cd services/control
SKEIN_WATCHDOG=1 .venv/bin/python -m skein.watchdog_agent
```

- 每轮读 `watchdog.signals`，新信号写审计，`kv` 去重。
- `SKEIN_WATCHDOG_TICKETS=1`：新信号自动建工单（`POST /internal/tickets`，dedup=`auto:signal:<kind>:<id>`），
  `SKEIN_WATCHDOG_DISPATCH=1` 时直接派给平台 `skein` 的 worker；每日上限 `SKEIN_TICKET_DAILY_CAP`（默认 5）。
- `SKEIN_DAILY_TICKET_HOUR=9`：每天 9 点建一张「每日巡检」工单（dedup=`auto:daily:<date>`）。
- `SKEIN_WATCHDOG_AUTO=1` 且有模型网关时，读取当前 `runtime/worker` 文本，让模型提一份修订，走 `prompts.propose` 进**金丝雀**。
- 永不自动升格；冻结、乐观锁、改幅上限由 `prompts` 负责。
- 没有模型时只观察/建单，不写词。

配置：

```ini
SKEIN_WATCHDOG=0
SKEIN_WATCHDOG_AUTO=0
SKEIN_WATCHDOG_INTERVAL=300
SKEIN_WATCHDOG_TICKETS=0
SKEIN_WATCHDOG_DISPATCH=0
SKEIN_DAILY_TICKET_HOUR=-1
SKEIN_TICKET_DAILY_CAP=5
SKEIN_CONTROL_URL=http://172.17.0.1:7800
```

## 6. 多信道入口

`POST /internal/trigger`（`X-Skein-Token`）：

```json
{"source":"im","origin_id":"m1","text":"帮忙看看","actor":"张三","mentioned":true,"parent_id":null}
```

- 有 Router 宿主时走完整准入/建单链路。
- 没有模型时只做程序层准入并记录事件。
- IM、GitHub、邮件适配器只需把事件转成这个 JSON；出站按信道定制的 writer 还没做。

## 8. 已知边界

- 常驻 Router 只做了单会话批处理，没有分片/多层过滤。
- 订阅直通是 best-effort：节点 busy 返回 nack 时事件已丢，后续需要 ack 确认与重试。
- 取消不杀 cc 进程，只丢弃结果。
- 链式召回、按信道定制的出站 writer、真正的异步 `start/stop` 工具协议还没做。
- Watchdog 的「判断方向是否偏离」仍需要模型与金标准；当前只处理确定性信号。
