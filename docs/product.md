# Skein 产品定义

> 2026-11-19 · 一句话、一个闭环、四个工作面。后续开发以本文为准。

## 一句话

**把真实用户反馈，变成可验收的修复。**

不是“又一个 Agent 平台”，也不是“论坛后台”。Skein 负责一件事：从小团队产品的真实反馈出发，调度 Claude Code 完成修复，最后由人验收。

## 给谁用

- 小团队的维护者 / 值班人，通常 1–3 个人。
- 每天要回答三个问题：**现在有什么要我处理？谁在干什么？卡在哪？**
- 不假设有专职 SRE、不假设有多租户、不假设有人愿意读长日志。

## 核心闭环

```text
论坛帖/评论/群消息
      │
      ▼
程序层准入（忽略 / 记账 / 处理）
      │
      ▼
工单（Thread 归并、去重）
      │
      ▼
派给节点上的 Claude Code 会话
      │
      ▼
交付（分支、提交、diffstat、自测总结）
      │
      ▼
人验收（通过 / 驳回）──► 合入 / 回写
```

人审是硬闸。系统可以自动采集、自动判断、自动执行，**不可以自动合入**。

## 四个工作面

一级导航只保留四个，回答四个不同的问题：

| 工作面 | 回答什么 | 包含 |
| --- | --- | --- |
| **工作台** | 现在要我做什么 | 待验收、卡住的派工、正在跑的任务 |
| **需求** | 这件事走到哪了 | 工单列表、详情、派发、验收 |
| **运行** | 谁在跑、卡在哪 | 总览拓扑、节点、Worker 会话、事件流 |
| **平台** | 为什么这么判、怎么改 | 准入矩阵、提示词、运行记录、审计、日志 |

原来的八个平级入口（工单/信号/总览/Worker/节点/事件/日志/平台）是功能清单，不是产品结构。信号并入工作台与运行，日志并入平台。

## 不是什么

- 不是聊天机器人：聊天只是入口之一，主界面是工单和运行状态。
- 不是 CI/CD：不自动合入、不自动部署；分支和 PR 由人处理。
- 不是通用多租户 Agent 平台：只服务自己的产品与团队。
- 不是监控大盘：指标只保留能直接指向动作的。工作台的阵图是导航——每个点都能点回对象，不做装饰性图表。
- 不是论坛后台：论坛帖子和评论是输入，不是主界面。

## 产品原则

1. **一屏回答“现在谁在干什么、卡在哪”。**
2. **每个数字都能点回具体对象。**
3. **系统安静，只有需要人行动时才出现。**
4. **人审是硬闸，按钮旁写清后果。**
5. **空态告诉人下一步做什么，不只说“暂无数据”。**
6. **中文优先；原始 ID 只在排障时出现。**

## 成功指标

- 从反馈进入到人验收的时间。
- 待验收队列的停留时长。
- 一次验收通过率。
- 派工超时 / 节点离线导致卡住的数量。
- 每天需要人工介入的次数。
